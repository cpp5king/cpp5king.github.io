# 架構與核心原則檢查

## 結論與已處理項目

正式程式維持完全離線、固定模板與條件產生文字。核心 draft-engine.js、case-session.js、template-loader.js 未修改，兩份民眾回覆模板文字未修改。

- F-01（已處理）：原「有設備」標籤不足以表達處理與排放。現在改為「油煙經污染防制設備處理後排放」，明確確認設備存在、油煙經處理後排放；不代表設備正常運轉。未選不表示否定，不另設尚待確認選項。切換「未設置污染防制設備」時隱藏並清除種類及其他自填，保留原輸出邏輯。
- F-02（已依業務定義釐清）：系統只在已派員完成現場稽查後建立紀錄，故固定派員文字是建立紀錄前提。不另設是否完成或尚未派員狀態。未填日期、時間仍顯示尚待確認，不取目前時間。
- 周界異味採樣：依使用者最新授權，採樣位置、程序、拍照簽名、標準作業程序及注意事項改為該模板固定文字，不再逐項勾選。此定義取代先前版本的程序勾選要求，不應套用到其他模板。
- 模板層級：空氣污染下並列餐飲異味與周界異味採樣－待檢驗結果。catalog 的 directTemplateId 使點選直接進各自表單；切換清空輸入及草稿。

## 保留的架構原則

- 無 AI、遠端 API、雲端、資料庫或案件持久化。輸入只在頁面記憶體。
- 相同模板版本與输入產生相同文字，不使用亂數或目前日期補值。
- 可變事實只取已輸入與選擇的內容；公司名、日期、時間、袋數不預填，採樣日期與稽查日期獨立。
- 固定模板、欄位及選項位於 data/templates；輸出可手動修改，不影響模板。
- 尚無獨立案件判斷規則引擎、決策樹或自動違規認定。showWhen／when 僅為表單條件。
