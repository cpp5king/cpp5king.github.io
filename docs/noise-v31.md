# 3.1 噪音流程整理

本版完整複製3.0，僅在 `C:\稽查助手\稽查助手3.1` 修改。雙擊同資料夾 `start.cmd` 即可離線開啟；不需安裝套件或連網。

## 入口

「噪音 → 噪音案件」使用主流程；「近鄰生活噪音」只顯示噪音樣態、管委會兩個原有欄位，透過固定 neighbor 分支沿用既有第6條公文。使用者不能在近鄰入口選舊第8條、第9條或未量測樣態。

原 `noise-case` 資料檔保留供內部委派及回歸測試，正式導覽未提供它的操作入口。舊介面測試只在測試記憶體設定直接入口，以繼續驗證舊量測引擎；正式 catalog 不採此設定。

## 未量測資料及組句

`data/templates/noise-main.js` 的 `unmeasured.reasons` 集中定義固定順序、顯示名稱、句子片段、適用類型。`mainReasons` 為識別碼陣列：

| 識別碼 | 原因 |
| --- | --- |
| locked | 大門深鎖 |
| notWorking | 未作業 |
| notOpen | 未營業 |
| notBuilding | 未施工 |
| source | 噪音源／設備未啟動 |
| notFound | 未發現所陳噪音情形 |
| other | 其他（搭配 mainReasonOther） |

已移除 `mainSiteStatus`、舊單選 `mainReason` 及現場無人。使用者選類型、勾原因後才展開場所；只有設備未啟動分支或量測分支顯示噪音源。

有設備未啟動時使用原設備句型，將鎖門／未運作事實置於設備前，其他事實置於後，未發現句不重複。其餘原因以原場所句型的 `statusText` 組合。順序由資料檔決定，不依勾選先後；未勾選的片段不加入。巡查及後續文字沿用本次使用者提供的共用核心模板。

「其他」嵌入完整公文，不再取代整份文件；民眾回覆保留前言與1999結尾。一般事實使用逗號及句子片段組合，不直接串接checkbox標籤。自填內容只作一次模板插值，不二次解析。

## 必填驗證及狀態

`NoiseMain.validate` 檢查當前分支所需事實，回傳具體缺漏提示：

- 第8條：場所；營建工程另需機具、作業內容，其餘需現場事實描述。
- 第9條量測：場所、作業情形、噪音源，量測數值／風速／背景資料是否足夠仍由原量測器判斷。有量才填；不要求額外補量低頻或Lmax。
- 未量測：至少一個適用原因及場所；設備未啟動另需噪音源；其他另需自填原因。
- 近鄰：噪音樣態及是否有管委會，公文分流與內容不變。

畫面以 `mainValidation` 顯示明確提示，未完成不開放產稿；会話層及模板引擎的可選工作流程驗證介面亦阻擋程式直接產稿。此介面只對有登記驗證器的模板作用，餐飲、異味與內部舊模板不新增要求。

通用checkbox增加 `item.when` 顯示與正規化支援，使不適用項目同時隱藏、停用及清除。日期、時間、區域等上游變更，清除下游；是否量測、類型、設施變更清除原因及現場／量測資料。取消設備未啟動清除噪音源；取消其他清除其自填內容。

## 規則與少量顯示變更

`scope.excludedActIds = ['exhaust']` 是本單位主流程範圍設定。控制器先使用既有第8條引擎，再將此項排除於候選集合，零候選判斷以排除後集合為準。正式規則資料仍保留排氣管，未改禁止時段、管制區、例外或假日條件；此項原為全天候，排除不改變平假日候選差異。

第9條量測檔僅將顯示字串改成「無法取得背景音量，未修正」。標準、公式、邊界及判定均未更動。共用摘要顯示民國日期、時許與既有引擎計算的適用時段，儲存仍為ISO日期、HH:mm。
