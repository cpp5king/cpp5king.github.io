# 稽查助手：規則式環保稽查案件輔助工具

Windows 本機完全離線的規則式環保稽查案件輔助工具。目前以「輸入現場事實 → 固定模板與條件 → 產生稽查情形及民眾回覆」為底層功能，尚未實作案件樣態規則引擎或自動違規認定。

正式程式不使用生成式 AI、OpenAI API、LLM 或其他 AI 模型，不依賴遠端 API、雲端、資料庫或帳號。AI／Codex 只作為開發工具，協助撰寫程式、重構、測試、除錯、整理模板及整理／實作使用者確認的規則。

核心原則是：相同已確認輸入與相同版本設定產生相同自動輸出；現場事實與案件判斷分離；未確認事實不得補寫；紀錄與回覆只使用固定模板與明確條件。完整開發依據見 [DESIGN.md](DESIGN.md) 與 [AGENTS.md](AGENTS.md)。

本系統僅在已派員完成現場稽查後建立紀錄，不另設完成稽查欄位。日期、時間未填仍顯示尚待確認，不填入目前時間。設備選項的完整用字明確確認處理與排放，不代表設備正常運轉。

目前正式內容為 **空氣污染** 下同層的「餐飲異味」與「周界異味採樣－待檢驗結果」，點選即直接進入各自表單。水污染、噪音及廢棄物僅顯示「開發中」，沒有加入案件文字、法規或判斷規則。

## 如何新增模板資料檔

### 1. 建立資料檔

將模板存為 `data/templates/你的英文檔名.js`，UTF-8 編碼；檔名可使用英數、底線、連字號。可複製目前模板的結構再依使用者提供內容修改，需移除不適用的餐飲欄位、文字及範例。

每個資料檔只登記一個模板：

```js
window.INSPECTION_CONFIG.templates.push({
  id: "你的唯一模板ID",
  categoryId: "air",
  caseTypeId: "restaurant-odor",
  title: "使用者提供的範本名稱",
  version: "1.0.0",
  fields: [ /* 使用者確認的欄位與選項 */ ],
  record: [ /* 使用者提供的稽查紀錄段落 */ ],
  reply: [ /* 使用者提供的民眾回覆段落 */ ]
});
```

上面只是格式說明，不是可直接使用的案件內容。`formTitle`、`instructions` 可設定表單說明；`demoLabel` 與 `demo` 可選，不填就不顯示範例按鈕。

### 2. 在 catalog.js 登記

在 `templateFiles` 加入一筆，id 必須與資料檔相同：

```js
{ id: "你的唯一模板ID", file: "你的英文檔名.js" }
```

同大類、同案件類型的新情境，新增模板檔並登記這一筆。若類型已有 directTemplateId，需移除它才會顯示多範本選擇。若新增案件類型，再於 `caseTypes` 增加 `id`、`categoryId`、`title`、`status: "active"`。若要啟用尚在開發中的大類，需在有已確認內容後將對應 `categories` 的 status 改為 active。

目前兩個案件類型各設定 `directTemplateId` 指向自己的模板 id，點選後直接進表單；新增同層獨立模板時，同樣新增 caseTypes 項目並設定 directTemplateId，模板的 caseTypeId 須與該項 id 一致。

**通常不必改 index.html 或 src 內的程式。** 改完重新整理即可。檔名缺漏、識別碼重複、分類錯誤、欄位條件錯誤會顯示載入錯誤，不會偷偷切回其他範本。

### 3. 欄位格式與輸出

每個欄位均需 `id`、`label`、`type`、`missing`。id 使用英文字母開頭，再接英數或底線；不可重複。`missing` 是沒有輸入時的字串，不可留空。

| type | 用途與相關設定 |
| --- | --- |
| text | 單行文字 |
| textarea | 多行文字 |
| date | 日期；format 使用 roc（民國年月日）、iso（YYYY-MM-DD）或 month-day（月日） |
| hour | 0～23 小時；suffix 指定字尾，目前為「時許」 |
| time | 時分 HH:mm，例如 00:07；空白或無效時間不會補值 |
| number | 數值；integer: true 表示整數，min 指定最小值 |
| select | 下拉選單；options、allowCustom、customLabel 等 |
| choiceGroup | 單選狀態搭配可複選子項，例如目前有／無設備 |
| checklist | 可複選項目；可帶自填欄位，目前用於會同人員 |

`record` 與 `reply` 是段落陣列，每個字串是一段，用 `{{欄位id}}` 指定填空。所有段落均支援替換；只出現在民眾回覆的欄位也會有輸入元件。重複使用同一標記只顯示一個輸入欄位，不必重填。輸入不被當成程式或 HTML 執行。

單選 `options` 的每筆資料：

- id：唯一選項識別碼；空值及 custom 為保留值。
- label：選單顯示文字。
- value：選取後填入稽查紀錄的文字，可以是空字串，表示使用者明確選擇省略。
- replyValue：可選，民眾回覆若需不同文字則指定；否則沿用 value。
- when：可選，格式 `{ field: "前方欄位id", value: "所需選項id" }`，只有符合條件才可選。

預設允許「其他，自行填寫」；設定 `allowCustom: false` 可關閉。自填值使用 `欄位idCustom` 儲存；`customType: "number"` 表示非負數值，`customPrefix`、`customSuffix` 設定前後文。若 `customReply: true`，會另外提供 `欄位idReplyCustom` 的回覆自填欄，可用 `customReplyLabel` 指定標籤。

`choiceGroup` 使用：

- showUnanswered: false：不顯示額外的尚待確認單選項，初始不選任何項。
- options：單選狀態，同樣有 id、label、value、replyValue；需要展開複選時設定 `usesItems: true`。
- itemsKey：複選值的唯一儲存鍵；不可和其他欄位或自填鍵重複。
- itemsLabel、separator、itemsMissing：子項標題、連接符號與未勾選提示。
- items：複選子項，每筆有 id、label；需要自填時加上 customKey、customLabel、missing。
- 狀態的 value／replyValue 使用 `{{items}}` 插入勾選子項。

`checklist` 使用 items 定義 id、label、value；有自填欄位時使用 customKey、customLabel、missing，可用 valuePrefix 在名稱前放入「委辦公司」等已提供文字。separator 連接選中項目，prefix／suffix 只在有勾選時套用。emptyValue 設為空字串表示未勾選不輸出，不能解讀為已執行。未設定 emptyValue 時沿用欄位 missing。

文字欄位可設定 suggestion 提供「使用常用文字」按鈕，只有使用者主動點選才填入；prefix 配合 avoidDuplicatePrefix 可避免重複「於」。

### 4. 條件及缺漏規則

欄位的 `showWhen` 與選項的 `when` 都使用單一明確等值條件：

```js
showWhen: { field: "equipment", value: "none" }
```

條件必須指向 fields 陣列前方已定義的欄位，以確保處理順序明確，避免循環。這是顯示／選項條件，不是自動判定污染或違規。

- 未填、選項不適用、日期或數值無效：使用 missing。
- 隱藏欄位：省略其輸出並清除當次值。
- 狀態改變：清除不再適用的選項、複選與自填內容；不會切回時自行恢復舊答案。
- 切換範本、大類或案件類型：清空整份輸入與兩份輸出，包括手動修改內容。
- 不根據敘述推論其他欄位，不把量測空白轉成 0，不自動預選事實。

現有欄位型別及等值條件能處理的範本，只需資料檔。未來若需要全新輸入元件或更複雜且已確認的條件，才擴充 renderer、engine 與測試；不承諾任意需求都能零程式修改。

## 周界異味採樣－待檢驗結果

此樣態僅適用於採樣已執行完成、檢驗結果尚未下達的案件；選用它是在確認這個前提，不是由程式推定採樣完成。沒有新增檢測合格、不合格樣態，也不判定檢測結果。餐飲異味原模板保留，兩者位於空氣污染下同一層級。

以下可變欄位只在採樣模板顯示：

- 現場基本資料：稽查日期、稽查時間（小時）、稽查對象／場所描述、現場作業情形。
- 會同人員：業者／該業人員、委辦公司、檢測公司、其他，可勾選；公司名稱及其他人員自由輸入，取消勾選即清除相應名稱。
- 採樣資料：採樣日期、開始／結束時間（時分）、袋數（正整數）。
採樣位置、程序、拍照簽名與標準作業程序均依使用者最新核定改為固定文字，不再提供欄位或勾選。固定文字只加入採樣稽查紀錄，不帶入餐飲異味模板。

稽查日期與採樣日期完全獨立。採樣日期欄選完整西元年月日，紀錄按使用者原稿顯示月日；不從稽查日期補採樣日期，也不自行推定結束時間的日期。袋數請填數字，例如 1，不填「1袋」；空白、0、負數與非整數顯示尚待確認。

會同名單只取勾選項目，勾選公司卻未填名稱時標示名稱尚待確認，不使用案例公司。

民眾回覆只使用使用者提供的簡短回覆原句，不帶入公司名、袋數、採樣時分或內部程序。切換其他樣態會清除全部採樣資料及草稿。示範見 [採樣待結果案例](docs/sampling-pending-example.md)。

自動測試已增加採樣資料、固定程序、跨日、輸出與切換清空的測試；欄位顯示測試使用記憶體 DOM 替身，並非實際瀏覽器或剪貼簿測試。

## 應用程式版本

整體程式版本集中於 `data/app-meta.js`。更新版本時只需修改該檔的 `version` 與 `label`；瀏覽器頁籤及頁首版本會自動同步。各案件模板自己的 `version` 保留作為模組／規則版本，不與 App 版本混用。
