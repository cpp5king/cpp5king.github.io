# 3.0 噪音案件主流程

本版由 2.9 完整複製。只新增主流程、未量測分支及導覽接線；第8條、第9條規則資料、判斷器、量測器與既有公文模板均保持原檔內容。餐飲、周界異味及第6條模板不變。

## 啟動與測試

雙擊 `C:\稽查助手\稽查助手3.0\start.cmd`，或直接開啟同資料夾的 `index.html`。不需安裝套件或連網。選擇「噪音 → 噪音案件」即進入主流程；「第6條／既有個別流程」保留原有操作。切換入口會清除案件資料及草稿。

PowerShell 測試命令：

```powershell
Set-Location -LiteralPath 'C:\稽查助手\稽查助手3.0'
node --test tests/*.test.cjs
```

## 資料責任

| 資料 | 欄位 | 責任 |
| --- | --- | --- |
| 案件共同事實 | `mainDate`、`mainTime`、`mainZone`、`mainHoliday` | 唯一可輸入的日期、時間、區域與必要假日確認 |
| 第8條現場確認 | `mainAct`、既有 `article8Exception`、例外查核、現場事實 | 候選及例外只由既有第8條規則產生；`none` 表示以上皆非 |
| 第9條入口 | `mainMeasure`、`a9Type`、`a9Facility` | 明確選擇是否量測，再確認法定音源類型 |
| 未量測事實 | `mainReason`、`mainReasonOther`、`mainSiteStatus`、`a9Subject`、`a9Source` | 原因與大門深鎖／現場無人獨立保存 |
| 第9條量測 | 原有 `a9*` 量測、風速、背景及出口欄位 | 交由 2.9 量測器處理；不新增標準表或修正公式 |
| 衍生狀態 | `mainRoute`、`mainBlocked`、顯示旗標、共用摘要 | 由本機主流程計算，不能當成使用者確認的事實 |
| 草稿 | `mainRecord`、`mainReply` → 原有會話輸出 | 可手動修改與複製；不修改模板，不儲存案件 |

欄位、選項與未量測公文集中於 `data/templates/noise-main.js`。主流程控制器為 `src/noise-main.js`，透過既有模板欄位複製與委派使用既有引擎，沒有複製法律條件。

## 串接方式

1. 將共同資料映射至既有第8條輸入，呼叫 `NoiseArticle8.evaluate`（內部使用 `filterActs`）。候選及假日必要性完全沿用同一規則來源。
2. 無候選、以上皆非或既有判斷器回傳公告例外成立時，`mainRoute` 自動變為 `article9`。核准營建工程原有附加查核仍顯示。
3. 第8條成立時，直接呼叫原 `noise-case` 模板產生公文，不開第9條。
4. 第9條只接收 `a9*` 事實，以及共同日期、時間、區域的唯讀映射。第8條禁止行為、例外與現場事實不傳入第9條文件。
5. 量測分支呼叫既有 `noiseArticle8` 工作流程中的第9條委派、`NoiseArticle9Measurement` 與文件產生器。此舊工作流程名稱屬歷史命名，本版未重構它。
6. 重測與結束按鈕直接委派原量測器。共同資料、行為、例外、是否量測或類型變動，清除相應下游資料；任何輸入變更立即清空舊草稿。

## 未量測文字界線

場所未運作只對使用者指定的四種類型提供未作業／未營業／未施工文字。擴音與其他設備不推論未營業。未發現分支不推論噪音源未啟動。額外現場狀態只在勾選後寫入。

「其他」未提供制式結論，因此原因必填，紀錄只使用自填原因及已勾選狀態，不補上未發現污染或違規結論。缺少場所／音源描述以「尚待確認」呈現。

## 驗證範圍

`tests/noise-main.test.cjs` 驗證主流程、未量測分支、量測與背景修正委派、無效量測出口、共同資料、條件變更清空，以及完整頁面事件。既有頁面回歸測試只增加進入「第6條／既有個別流程」的導覽步驟；原功能輸出預期未修改。

正式規則中的排氣管行為不限時段，因此一般有效輸入至少會有此候選。「無候選」測試僅於測試記憶體暫時移除此項，未更動正式規則資料。

介面自動測試使用 DOM 替身，不宣稱已實測 Windows 瀏覽器與系統剪貼簿。測試確認程式符合使用者核定條件，不代表另行查證法規或現場事實。

`tests/fixtures/version29-manifest.json` 是複製前 2.9 全部檔案的 SHA-256 清單，用於確認原版本與保護模組未修改。歷史文件保留，3.0 現況以本文為準。
