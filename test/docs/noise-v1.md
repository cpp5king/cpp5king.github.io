# 噪音案件 V1

入口：首頁 → 噪音 → 噪音案件 → 選擇四種案件樣態。

文字來源為使用者提供的 V1 原稿。所有分支由使用者選擇，不自動查標準、修正背景音、判定禁止時段或從量測值判定超標。日期、時間、管制區、音源別、公告條款、標準值均不預填。

- 近鄰：有無管委會決定稽查情形，民眾回覆使用提供的共同原稿。
- 第8條：使用者選用直接告發樣態；公告條款人工輸入，不存放舊公告字號。
- 第9條：人工選擇符合／超標；只在明確選擇已說明時加入陳情人說明句。背景音說明須選擇既定句或自行填寫，不計算差值。
- 一般噪音與低頻可複選。V1 依指示沿用同一份原稿及數值欄位，未另外產生低頻專用敘述或分組數據。
- 未量測：音源未運轉／未發現所陳噪音時，使用者再選擇一般音源或擴音設備的已提供用字。天雨回覆依原稿，不自行加上1999結尾。「其他」無核定原稿，提供兩份文字自填欄位，未填顯示尚待確認。

固定公文不顯示在表單。必要分支選項未填時，不選擇任何結論段落。已選分支中的可變欄位缺漏仍顯示尚待確認；產出後須核對。

## 資料與程式

`data/templates/noise-case.js` 保存欄位、選項與原文。`catalog.js` 登記噪音案件。表單沿用現有 renderer，固定文字不作為輸入欄位。

共用引擎只新增兩項資料能力：

- `showWhen: { field: "scenario", operator: "in", value: ["article8", "article9"] }`：欄位適用於列出的樣態。
- `recordVariants`／`replyVariants`：各筆為 `{ when: { field, value }, text: ["含欄位標記的原稿"] }`。依正規化後事實選擇唯一符合分支，未符合沿用原本 record／reply；同時符合多筆時報錯，不自行裁決。

未設定上述能力的既有模板沿用原本行為；餐飲與採樣資料檔未修改。這是文字模板分支，不是自動案件法規判斷引擎。

測試：`node --test tests/noise.test.cjs`；全套：`node --test tests/*.test.cjs`。
