# 3.3 資料保留與日常測試

由3.2完整複製建立。双擊本資料夾 `start.cmd` 完全離線啟動。只調整噪音主流程的資料相依性、量測作業固定文字、測試分類及目前版本標示。

## 智慧保留

`src/noise-main.js` 的 `resetChange` 處理使用者變更事件，`reconcile` 以既有第8條候選引擎、第9條標準查詢結果篩除不適用資料；`prepare` 仍呼叫原有引擎重算時段、背景修正及最終結果，沒有新增第二套法規條件或标准表。

- 日期／時間／管制區修改，保留場所、噪音源、是否量測、類型、仍適用的數值與風速。新日期必須重新確認假日；不影響候選的時間不顯示假日題。
- 第8條行為仍在候選則保留，已失效則清除該行為及例外、專屬事實。第9條資料不因第8條分流暫時隱藏而消失；只有當流程實際進入第9條才可使用它產稿。
- 第9條改類型，清除新類型無標準的項目（例如非營建工程的Lmax、擴音設施的低頻）及對應背景。離開第6款清除設施子類；離開工廠清除歲修核備背景。
- 未量測原因保留仍適用的checkbox，自訂其他原因僅在仍勾選其他時保留。取消設備未啟動後噪音源隱藏但可保留，其內容不會寫入該未量測公文。
- 仍需背景處理的項目保留原背景值或無法取得例外；新標準下未超標的項目清除背景。正常背景與例外互斥；取消例外清除原因及核備資料。
- 改成不量測時，量測、背景、風速及量測專屬條件不再適用而清除；現場基本資料保留。有效性不足時保留可用原始資料但不產生最終公文。
- 修改影響量測的輸入會取消前一次「結束量測」選擇；無效數據需依既有重測／結束流程重新處理。

噪音模板將選項的顯示條件改用 `displayWhen`，資料有效性由上述流程處理。共用渲染器、卡片、餐飲及異味的顯示／清值機制未修改。

草稿與輸入分開：既有 `clearDraft` 機制仍會在編輯時立即清空兩份正式草稿。重新產稿才使用新的時段、標準及結果。回首頁重新開始案件仍透過原有 session 完整清空；量測重測仍清除該次量測與背景資料。

## 固定量測作業文字

主流程移除 `a9Operation` 輸入欄及其必填檢查。`NoiseMain.article9` 在 `mainMeasure === 'yes'` 時提供 `NOISE_TEXTS.main.measuredOperation`，定義於 `data/texts/noise-main.js`，值為「現場作業中」。原模板 `稽查時{{operation}}` 不變。未量測分支仍依checkbox產生文字，不使用此值。第8條作業內容仍依使用者填寫。

## 版本標示

`index.html` 標題／頁首及三個噪音模板 `noise-main`、`noise-neighbor`、內部 `noise-case` 的 version 為3.3。規則資料版本、歷史說明、fixtures保留原值，未盲目取代舊版號。

- 規則／數值與流程測試持續執行。新增 `tests/noise-v33.test.cjs`，驗證保留與清除、標準重算、背景及工廠核備、固定作業文字、草稿失效與重設。
- 更新 `noise-main.test.cjs`、`noise-v31.test.cjs`、`noise-cards.test.cjs`，取消舊的全面清空要求及不存在的作業輸入操作。
- `noise-text-contracts.test.cjs` 保留1999、巡查尾段、背景未修正用語、條項款及文字集中檢查。原有其他文字契約仍在；修改固定契約時，對應文字測試報錯是正常的。
- 61份3.1.2完整公文比對移至 `tests/migration/v312-to-v32.cjs`，根目錄日常命令不會執行。舊fixture保留，也供規則資料比對，未刪除所有文字測試。

歷史遷移驗證只讀指定3.2版本，在PowerShell執行：

```powershell
$env:INSPECTION_MIGRATION_BASE = 'C:\稽查助手\稽查助手3.2'
node --test tests/migration/v312-to-v32.cjs
Remove-Item Env:\INSPECTION_MIGRATION_BASE
```

未指定來源時該migration測試跳過。它驗證歷史3.2，不把3.3固定作業文字與舊公文綁在一起。一般文案調整不需更動法規引擎；日常邏輯測試以資料／狀態為主，對應的固定文字契約仍需維護。

驗證結果：日常307／307通過，0失敗、0跳過；另行指定3.2來源的歷史遷移測試1／1通過（61組案例）。來源雜湊清單保留於 `tests/fixtures/version32-manifest.json`。
